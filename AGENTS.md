# AGENTS.md — Backend: Sistema de Gestión Académica

## Developer Commands

```bash
# Local dev (requires venv + PostgreSQL + Redis)
daphne -b 0.0.0.0 -p 8000 config.asgi:application    # ASGI dev server (needed for Socket.IO)
python manage.py runserver 0.0.0.0:8000               # Fallback WSGI
celery -A config worker --loglevel=info               # Celery worker (separate terminal)
celery -A config flower --port=5555                   # Celery monitor (optional)

# Docker (recommended)
docker-compose build; docker-compose up
docker-compose exec web python manage.py createsuperuser
bash scripts/verify_docker_setup.sh

# Database
python manage.py migrate
python manage.py makemigrations <app_name>

# Seeds (idempotentes, orden requerido)
python manage.py seed_catalogs        # Catálogos del sistema
python manage.py seed_permissions     # Permisos + Roles
python manage.py seed_test_data       # Datos de prueba

# Tests — MUST use --settings=config.settings.test (SQLite, eager Celery, MD5 hasher)
python manage.py test --settings=config.settings.test                     # All
python manage.py test apps.iam --settings=config.settings.test            # Single app
python manage.py test apps.grading.tests.test_models --settings=config.settings.test  # Single file

# Coverage
coverage run --source='.' manage.py test --settings=config.settings.test; coverage report -m
```

## Architecture

**Layered pattern per app**: `models/` → `repositories/` → `services/` → `api/` (serializers, views, urls). Some apps (e.g. `iam`) use DDD structure: `domain/` → `infrastructure/` → `application/` → `api/`.

- `config/settings/` — split config: `base.py`, `local.py`, `production.py`, `test.py`. Default: `config.settings.local`
- `apps/core/` — shared utilities: `StandardResponseRenderer`, `custom_exception_handler`, `StandardResultsSetPagination`, `ok_response()` / `error_response()`, `HasPermission`, `RoleBasedFilterBackend`, `SoftDestroyMixin`, `SoftDeleteModelMixin`
- `AUTH_USER_MODEL = "iam.User"` — Custom user in `apps/iam/infrastructure/models.py`. Login by **username** (autogenerated: first letter of name + first last name + numeration if duplicate).
- `sys.path` inserts `apps/` as root package in `config/settings/base.py` (line 13)

**Apps** (11 apps): `core`, `iam`, `people`, `institutions`, `students`, `academic`, `grading`, `attendance`, `behavior`, `analytics`, `integration`

**API routes** (see `config/urls.py`):
- `/api/iam/`, `/api/academic/`, `/api/institutions/`, `/api/grading/`, `/api/students/`, `/api/analytics/`, `/api/attendance/`, `/api/behavior/`, `/api/people/`, `/api/integration/`
- Per-module docs: `/api/schema/{mod}/`, `/api/docs/{mod}/`, `/api/redoc/{mod}/`
- Public docs (no auth): `/api/schema/`, `/api/docs/` (Swagger), `/api/redoc/` (ReDoc)

## API Contract

All responses via `StandardResponseRenderer`: `{"ok": bool, "data": ..., "msg": "..."}`
- Default permission: `IsAuthenticated`
- Auth: JWT Bearer tokens via `djangorestframework-simplejwt`
- Pagination: `StandardResultsSetPagination` (page_size=20, max=100, param="page_size")
- Public endpoints: `POST /api/iam/login/`, `POST /api/iam/refresh/`
- Frontend expected at `localhost:3000` (CORS)
- Validation errors return HTTP 422

## Critical Conventions

- **NO `Model.objects.query()` in views or services** — all ORM in `repositories/` layer
- Use `ok_response(data)` / `error_response(msg)` from `apps.core.utils.responses`
- Model names use `Camel_Case`; methods/variables use `snake_case`
- `.env` loaded via `python-dotenv` in `config/settings/base.py` (copy `.env.example`)
- `db.sqlite3` is gitignored, local fallback; Docker uses PostgreSQL
- **NO linter/formatter config** — no ruff, no black, no pyproject.toml, no pre-commit
- **NO central `catalogs/` app** — each domain app manages its own catalogs
- **NO `configuration` app** — it was removed; do not reference it

## Views & Permissions

- **All modules use ViewSets** (no `@api_view`). RESTful with `router.register`
- Custom routers: `InstitutionsRouter`, `GradingRouter` (map `"get"` instead of `"retrieve"`)
- Action permissions via `action_permissions` dict on each ViewSet
- Permission class: `HasPermission` from `apps.core.api.permissions`
- Permission constants: `apps.core.constants.permissions` — frozen dataclasses per module (`iam.VIEW_USER`, `grading.CREATE_NOTE`, etc.)
- `RoleBasedFilterBackend` enforces row-level security via `user_category` property
- Superusers bypass all permission checks

## Soft Delete

- `SoftDestroyMixin` — converts standard `destroy()` to logical delete (`is_active=False`)
- `SoftDeleteModelMixin` — adds `POST /{id}/soft-delete/` endpoint with optional `{"confirm": true}` cascade
- See `SOFT_DELETE_CONTRACT.md` for detailed cascade rules (institutions module)

## Test Setup

- Uses Django `TestCase` + DRF `APIClient` — **not pytest**. No conftest/pytest.ini
- Tests use `force_authenticate(user=...)`, not JWT tokens
- Test fixtures created manually in `setUp()` — no factory library
- **Must use `--settings=config.settings.test`** — SQLite, eager Celery, locmem cache, MD5 hasher
- Test DB file: `test_db.sqlite3` (gitignored)
- Grade submodule tests (`activity_type/tests/`, `student_note/tests/`, `evaluation/tests/`) are empty (only `__init__.py`)

## Docker Services

| Service | Port | Notes |

| web | 8000 | `WAIT_FOR_DB=true`, `RUN_MIGRATIONS=true`, `RUN_SEED=false` default |

| redis | 6379 | Celery broker + Django cache |
| celery | — | Worker: `celery -A config worker` |
| flower | 5555 | Celery monitoring UI |

Entrypoint (`scripts/entrypoint.sh`) waits for DB, runs migrations, optionally runs seeds.
